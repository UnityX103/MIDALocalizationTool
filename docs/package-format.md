# 本地化 ZIP 交付边界

本编辑器不直接读取 Unity 工程。Unity 导出 ZIP，编辑器导入并编辑，再导出数据 ZIP 给 Unity 回收。

## 清单与片段

ZIP 根目录为 `manifest.json`，每个片段分别位于 `parts/<partName>.json`。同片段的多个目标语言任务可放在同一片段文件中，不将全部片段合并为一个数据文件。

- 纯数据包使用清单 v2。
- 附带预览视频的输入包使用清单 v3，同一片段包含 `previews/<partName>/video.mp4` 和 `previews/<partName>/dialogue-map.json`。
- 媒体必须成对，片段和 recordingId 必须一致。清单记录路径、SHA-256、byteLength 及共同版本标识。
- 内部对话数据保留 `mida-localization` v1 格式、projectId、packageId、fileVersion 及来源哈希；清单版本与内部对话格式版本不是同一概念。
- 导出只包含选择交付的任务，生成数据清单 v2 和每片段 JSON，不回传视频。

解析实现以 `package_io.py`、`src-tauri/src/package.rs` 和前端导入校验为准。未知资产、旧单文件清单 v1、示例任务、不安全路径及清单外文件被拒绝。

## 翻译工作量与回执

编辑器交付 ZIP 的根 `manifest.json` 增加 `delivery` 和 `workload`：
独立交付身份、当前进度、累计与待交接汉字数、逐笔历史工作明细。
重复导出相同内容复用同一快照，不清零待交接量。被新中文替换或删除的已完成工作仍保留。
下一次 Unity 来源包可在同一清单携带 `workReceipts`，编辑器只按匹配的回执自动确认交接；
无回执的旧包保持兼容，不推测已验收。回退历史不回退累计台账和回执。

不新增 ZIP 文件或清单资产类型，不复制台账到每个片段 JSON。浏览器和桌面端复算汇总并校验范围。
完整字段、计数范围、幂等与 Unity 接收要求见 [工作量协议](workload-protocol.md)。
`han-v1` 只计固定范围汉字，不计标点、数字、英文；功能启用前的劳动不自动追溯。

## 章节本地化单元

章节仍使用 `localization-dialogues`，原 `id`、`partName`、`path` 与任务版本身份不变；章节名就是该单元的 `partName`，文件仍为 `parts/<unit>.json`。清单对话资产、单元 JSON 根及 `tasks[]` 可携带 `unitKind: "chapter" | "part"` 和 `chapterName`，存在时三处必须一致。旧包缺少这些字段仍可导入，不从包名推断单元类型。编辑器保留元数据、来源快照及复核状态，章节与其他任务一样支持编辑、确认、选择交付和版本合并，不提供章节录制。

章节清单资产可包含 `previewPartNames`，仅声明**本 ZIP 实际携带的关联子片段媒体**，不是全量所属片段，也不是后续媒体的排他允许列表。每个名字必须是合法且不重复的实际片段名，不能指向章节自身。v3 中每个声明都必须有配对视频与 map，且 map 的 `chapterName` 等于该章节名、至少一个事件的 `sourceUnit` 等于该章节名；这些子片段可以不附带自己的对话 JSON。未被章节声明的媒体仍必须有对应片段对话资产。章节自身不能拥有视频资产。

预览 map 保持 `mida-localization-preview` v1，可增加 `chapterName`；事件可增加 `sourceUnit`，记录真实运行时对话包来源配置名，不从 key 推断。原 `packageName`、`occurrence`、`frame`、`timeMs` 和包名哈希算法不变。`chapterName` / `sourceUnit` 为空、null 或缺省均按无来源信息兼容，不生成章节定位。带章节信息的录制目录可能包含不在本 ZIP 中的片段或章节对话，仍校验完整目录和录制包哈希、事件归属及时间边界，不用当前章节任务替代录制目录。

章节“查看视频”只使用当前项目中同时满足 `map.chapterName === task.partName`、`event.sourceUnit === task.partName`、`event.packageName === 目标包名` 的实际事件。一个目标直接定位到其真实片段的 `timeMs`；多个片段或多次出现时提供片段、出现次数与时间的选择，没有映射就不提供跳转。全局、场景、FGUI 和原片段任务不由这些字段自动改成章节。

只含章节 JSON 的数据 ZIP、`previewPartNames: []` 的章节都可先导入，之后再导入匹配的片段录像即可关联。清单原声明随工作区保存；导航和工作区媒体归属以实际 map 来源为准，不依赖最近一个 ZIP 的声明列表。同任务版本可以补充章节元数据而不覆盖本地译文和草稿，已经明确的 `unitKind` 不能静默改变。

导出仍只生成 v2 数据 ZIP：`unitKind/chapterName` 写回清单对话资产、每个单元 JSON 根和对应任务；`previewPartNames` 只放章节清单资产，因输出不含媒体而写为 `[]`。不把历史声明当作输出包的媒体，不把 `previewPartNames` 写入 JSON 根或任务。录制 map 原有来源字段保留在本地工作区与媒体缓存中，不随数据 ZIP 回传。

## 小游戏资产文本与显式空译文

小游戏仍使用 v2 数据 ZIP / v1 JSON 和既有 `localization-dialogues` 资产类型，不改变章节包协议。Unity 在任务中保留 `sourceKind=unity-minigame`、`assetProtocolVersion=1`、`exportId`、模块和子表 ID/GUID；词条保留 `assetGuid`、`notes`、`allowEmpty`。这些只读扩展字段随导入、工作区持久化、版本合并及导出原样保留；客户端不据此直接修改 Unity 文件。

小游戏任务列表、当前标题与导入预览显示 `moduleId / tableDisplayName`，没有显示名时使用 `tableId`；缺少有效模块/子表标签时回退 `partName`。内部身份、版本匹配、ZIP 路径与媒体索引仍使用原 `partName`，章节任务显示不变。

只有任务的 `sourceKind` 严格等于 `unity-minigame`、`assetProtocolVersion` 为数字 `1`，且词条 `allowEmpty` 严格为布尔 `true` 时，空字符串或空白译文才能确认。标记缺失、类型错误、其他来源、其他协议版本和所有章节任务继续要求非空译文；不能只在章节词条加 `allowEmpty` 绕过规则。

符合条件的空译文可以点击“确定”、自动保存及输出 ready 包，旧版合并时保留已确认空值，不用原有非空译文回填。空值本身不触发 pending，但已有源变化、强制复核或问题标记仍要求确认；pending 空值不自动完成。前端确认/导入归一化/完成度计算及 Python、Rust 的 ready 校验使用同一来源限定，draft/ready 均不移除原有安全检查。

浏览器服务 `serve.py` 的导出前置校验与 `package_io.py` 的 ZIP 读写校验共用 `accepts_translation`；桌面 Rust 校验保持同一来源/版本/布尔条件。`import-worker.js` 只解析 JSON 并校验哈希，无须增加空译文逻辑。

Unity 回收仍以原资产规则、导出快照、完整 key 集合、模板参数与源/目标指纹为准；客户端允许确认空值不代表拥有写入授权，原文含参数时可能仍被 Unity 拒绝。旧桌面版本不能确认空译文，需要使用包含此兼容改动的客户端。

## 版本合并

### 词条来源快照（只读）

- `currentSource`：最新正式中文原文。
- `localizationSourceAtExport`：同 key 本地化表 `origin_text` 的旧中文，缺失为空串。展开对话包时，有非空白内容才显示「旧本地化中文」整块；与最新原文相同也显示，空串或纯空白连标题一起隐藏。收起后的摘要只使用最新原文和目标译文，不包含旧中文。
- `translationAtExport`：导出前所选目标语言的译文，不一定是英文。
- 可选 `englishTranslationAtExport`：同 key 本地化表 `text_en` 的旧英文，与任务语言无关，缺行或缺列时显式为空串。缺少该字段的旧包仍可导入；兼容读取仅在 `en` 任务使用 `translationAtExport`，其他语言返回空串。显式空串不触发回退，不使用可编辑 `translation` 回填。
- `translation` 仍是可编辑目标译文。编辑、确认、自动保存、备份、历史回退和再导出均保留来源快照；不会把最新原文、旧工作区原文或目标译文写成旧中文。旧存档中的 `previousSource` 不再用于显示旧本地化中文，新合并不再生成此别名。
- 有新任务版本时保留新包提供的快照；同任务版本且原有哈希和该词条三个来源快照一致时，可按 key 补充此前缺失的 `englishTranslationAtExport`，保留本地译文、草稿和复核状态，不覆盖已经存在的旧英文快照。
- 旧包缺少的可选字段在持久化与再导出中保持缺省，兼容读取不会修改原始字段。新增字段只接受字符串（含空串），拒绝 null、数字或对象。ZIP / manifest 版本不变，仍每片段一份 JSON；不增加旧英文对比界面。

同一项目、同一片段、同一语言且 key 相同的词条可匹配。当前中文与用户处理过的中文基线一致时复用译文；不同则保留已有译文并标记待处理，避免新包覆盖未交付的编辑成果。用户点「确定」后回到预览状态。

传入的版本身份由 ZIP 提供，不生成占位项目或伪造来源版本。首次启动不内置任何任务，空白工作区不能导出。

## 预览媒体

v3 任务 ZIP 允许部分片段含媒体、其他单元仅有文本。除上述章节显式声明的子片段外，每个媒体片段必须包含自己的对话 JSON；声明了媒体的片段要求视频与映射成对、录制身份一致且归属有效。浏览器与桌面导入遵循相同的章节规则。

Unity 的独立 `mida-localization-preview-bundle` 视频 ZIP 不属于翻译任务包，本编辑器不通过它创建任务或补充媒体；要导入预览，请使用包含对话 JSON 的 v3 任务 ZIP。

时间映射使用 `mida-localization-preview` v1；事件含包名、occurrence、frame 和 timeMs。包名按 UTF-8 字节词典序排序并去重，对紧凑 JSON 数组计算 SHA-256。完整有效包清单与实际录到的包清单分别保存，不把未覆盖分支当作版本落后。

播放器可置于窗口右侧或底部；只有视频可用且包含目标对话包节点时显示「查看视频」。章节按上述明确来源事件提供目标选择，旧映射仍用于原片段播放。编辑器不录制或导出视频。

新任务导入成功后，清除同项目同片段旧媒体；片段对话任务的新包不含视频时同样清理。章节附带的实际子片段媒体参与相同事务与清理；只导入章节文本不会清除未随包更新的子片段录像。取消或保存失败不清理旧媒体，其他片段不受影响。备份保留媒体引用而不复制视频，被清理的旧视频不能通过备份恢复。

## 导入进度与取消

导入按读取上传、解压校验、片段整理、合并和保存显示进度。桌面端在后台线程读取 ZIP，浏览器服务使用独立请求查询进度和取消，避免排在上传锁之后；前端通过 Worker 解析片段 JSON，并分批校验、合并词条，让界面持续响应。

从开始读取到确认、合并期间锁定编辑区、空间切换、保存和导出，保留取消按钮；关闭弹窗或按 Escape 同样请求取消。取消等待后台停止并清理本次临时媒体，合并阶段恢复原工作区，不删除原视频。最终原子保存阶段显示不定进度并禁用取消，保存成功后才结束导入，避免已提交数据被误报为取消。

## 容量与安全

- 文本单文件不超过 64 MiB，总计不超过 128 MiB。
- 视频单文件不超过 512 MiB；ZIP 压缩及解压总量不超过 2 GiB。
- 最多 200 个片段、600 个清单资产、601 个 ZIP 条目、1000 个语言任务、100000 条对话。
- 拒绝路径穿越、重复路径、符号链接、加密包、不匹配的哈希与清单外文件。
- 浏览器服务仅监听本机并校验 Host / Origin；桌面端通过原生文件选择器或拖入 ZIP 获取输入。

自动保存是本机恢复机制，不代替独立设备备份。交付前仍应保留导出的 ZIP。
