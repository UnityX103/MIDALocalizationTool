# 生产连续性与恢复

本说明对应当前修复源码；安装包需由既有 CD 流程重新生成后才能包含这些改动。
桌面与浏览器工作区仍相互独立，跨编辑器只通过用户选择的 ZIP 交换。

## 存档无法打开

1. 打开「偏好 → 历史记录与自动备份」，选择可用备份先只读查看。
2. 点击「恢复」并确认，将有效快照设为当前工作区；原始存档单独保留，不直接覆盖销毁。
3. 也可以在「翻译任务」中切换健康空间。坏的默认空间不应阻断其他空间的加载。

桌面原始索引保存在该空间的 `workspace/recovery/`；浏览器在独立 IndexedDB 中保存原始恢复记录。
恢复会更新存储代次，旧窗口不能继续覆盖恢复后的数据。最新台账能独立验证时继续保留；
无法读取或验证时使用备份台账，并明确提示原始数据仍保留供核对，不声称累计量完整。

坏备份单独标记不可用，健康当前数据仍可保存和交付。首次发现损坏时保护已有片段文件；
之后按当前、正常备份、归档和保护引用清理无关旧版本。坏备份与恢复原件不会因为普通十份备份轮换而被删除。
这些保护数据可能占用额外磁盘空间，不自动推断用户是否已完成核对。

## 容量与浏览器超限存档

每次导入最多 200 个片段；合并后的整个语言空间最多 1000 个片段、100000 条词条。
导入合并前检查总量，保存与恢复也检查同一上限，避免产生能保存却无法再打开的工作区。

浏览器旧存档超过总词条上限时，恢复对话框提供「拆分超限存档并恢复」。
按完整片段拆成每组不超过 100000 条的快照，首组恢复，其他组保存为不会随普通备份轮换删除的恢复分组。
草稿、候选译文和媒体引用按片段分配，原始存档另行保护；分组共用原台账，不截断工作记录。
单个片段本身超过 100000 条时拒绝拆分，应核对原始存档并从来源拆分 ZIP。

词条列表每页最多 100 句。普通确认传输词条修改和新增工作记录，并合并同片段排队中的确认；
候选译文持久化成功后才更新当前显示。完整保存与逐句保存按队列顺序提交，保存失败保留未保存标记与窗口中的修改。
磁盘仍按完整片段 JSON 写入，搜索、进度统计和首次加载仍会扫描数据；大任务实际响应时间需要专门验收。

## 台账达到上限

底部工作量问号 →「工作量归档与继续生产」→「保存归档并创建新台账」。
先确定正在编辑的译文。归档先冻结完整记录、历史交付和当前任务的固定交付包，成功持久化后再创建新台账。

- 旧记录和交付身份保持不变，累计字数保留；同一词条、同一原文不重新计数。
- 未收到回执的工作仍为待交接；归档不会自动验收。
- 「导出归档 ZIP」生成归档时当前片段的固定数据包，每包最多 200 个片段，仍可导入匹配回执。
- 「导出完整台账 JSON」包含完整历史工作明细及后续确认摘要。已移出的片段须核对原交付 ZIP，不能仅凭台账重建片段数据。

桌面归档以不可变分块和最后发布的清单保存到 `workspace/ledgers/`，片段引用由独立侧文件保护。
浏览器归档保存到本编辑器 IndexedDB，引用被纳入清理保护。活动工作区只保存归档摘要。
清空本编辑器全部缓存会删除这些本地归档，重要交付应另行保留导出的 ZIP / JSON。
协议身份和统计口径见 [工作量协议](workload-protocol.md)。

## 浏览器中断视频导入

新导入在创建暂存目录前登记事务。等待确认时续租；已保存到工作区但尚未完成媒体提交的 token
被保护，即使长时间离线也不按过期事务删除。启动时核对各空间及恢复原件中的未完成 token。

未保护、超过 24 小时的上传或暂存，以及无登记的旧暂存目录，会在服务启动、新导入或租约核对时清理。
这是活动触发的清理，不是后台定时任务。媒体核对失败会提示警告，不阻断已保存译文的加载。
升级前已有、无法确认是否被浏览器引用的暂存保守保留，避免删除尚未提交的真实视频；不会自动将未知遗留数据视为垃圾。

## 更新下载

Tauri 固定为 2.11.6，rustls 锁定为 0.23.45。更新元数据限制为 4 MiB，安装资源限制为 512 MiB；
同时检查声明长度与实际累计字节，超限在追加缓冲区前拒绝。有效安装资源仍须通过原有签名校验。
安装资源仍使用有上限的内存下载，并非流式写入磁盘；512 MiB 不是整机内存占用上限。

`src-tauri/vendor/tauri-plugin-updater` 是带许可证的 2.11.0 源码补丁，用于约束插件自身读取。
升级上游插件时需重新核对字节上限及签名路径，详见其 `LOCAL-PATCH.md`。
