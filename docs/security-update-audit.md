# 凭据与更新源检查（2026-09-13）

## 检查结论

- 检查 GitHub 当前 main、v1.0.1，以及本地所有可达引用的 84 个历史文件对象：未发现当前 CNB 凭据的完整值、常见 CNB 凭据硬编码格式或 PEM/OpenSSH 私钥块。检查程序只输出命中文件与对象标识，不输出凭据内容。
- GitHub 仓库 Actions Secrets 仅有 TAURI_SIGNING_PRIVATE_KEY，这是已有应用自动更新的校验密钥，不是 CNB token。仓库 Variables 与 Environments 列表为空。GitHub 工作流不设置、不导出 CNB 凭据。
- 源码里的 CNB_TOKEN 为环境变量引用；CNB 的自动同步任务使用 CNB 平台临时注入的 token，GitHub 云构建不使用它。
- 本地 origin 的 fetch 地址为用户指定的 GitHub HTTPS 仓库，push 使用同仓库 SSH 授权；cnb 作为镜像 remote 保留。没有把凭据写进 remote URL。

这是对当前可访问配置与可达提交的检查，不覆盖已删除、不可访问的历史对象，也不能证明不存在未知格式的秘密。未发现泄露，不执行凭据轮换或重写历史。

## 更新源修正

此前发布的 1.0.1 只读取 CNB，没有 GitHub 回退。本次源码补齐：

| 状态 | 选择 |
| --- | --- |
| CNB 与 GitHub 最新正式版相同 | CNB 优先 |
| CNB 最新版低于 GitHub | GitHub 最新版 |
| CNB 无法访问或最新清单不可用 | GitHub 可用最新版 |
| GitHub 无法访问 | 使用已查询到的 CNB 版本 |
| 两端都不可访问，或已发现最新版的清单都校验失败 | 报错，不执行更新 |

Release 标签与更新清单版本必须一致；清单和安装包 URL 必须属于对应来源、当前项目和对应版本。原有签名校验、强制/可选策略以及确认后安装行为保持不变。

“关于”展示及复制的代码仓库改为 GitHub。桌面与浏览器版本历史均以 GitHub 为主，失败可读 CNB。

已完成语法、前端生成及 Rust 编译检查；按项目规则未运行测试或对真实用户数据执行安装。当前修正尚未发布，旧安装包不会因仅修改源码自动获得双源逻辑。
