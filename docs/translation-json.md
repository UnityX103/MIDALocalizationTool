# 原文与候选译文 JSON

JSON 是外部翻译辅助文件，不是 Unity 交付 ZIP，不包含验收回执，也不推进交付版本。

## 使用流程

1. 在左侧勾选任务，点击底部“导出原文”，弹窗默认关闭“导出已翻译的内容”。默认只导出尚未确认的词条，包含原文变化后待重译、待复核的词条；没有这类词条时确认按钮不可用。开启开关后导出所选任务全部词条，已确认词条附带当前译文。未确认的编辑草稿和待校验候选不会写入 JSON。弹窗显示未翻译、已翻译和本次导出的条数。
2. 在弹窗内选择目标目录后确认导出。桌面端使用系统目录选择器；支持目录选择的浏览器使用目录授权；不支持的浏览器明确显示“浏览器下载目录”，保存位置由浏览器下载设置决定。
3. 保留 JSON 的结构和来源字段，只填写或修改每条词条的 `translation`。未确认词条的初始值 `null` 表示尚未填写；已确认词条保留当前译文字符串，可修改后导回。普通词条的空串、纯空白会跳过。只有原任务明确允许空译文时，空字符串才可以作为候选。
4. 点击“导入译文”。可用译文作为候选保存，自动切换至对应任务及“待校验”筛选。已确认词条也可接收候选，已有译文与待校验译文允许并存。原译文和编辑草稿保持不变，翻译进度、累计工作量和交接量均不增加，已确认状态不回退。
5. 有候选时，当前译文上方显示可编辑的“待校验译文”输入框。修改后点击旁边的“确认”，直接替换当前译文（包括该句尚未确定的编辑草稿），不再弹二次确认。译文与工作量记录一起保存成功后才正式生效；保存失败可重试。只修改待校验框不计数，编辑内容会随手动保存、切换空间和正常退出保存；意外关闭前仍建议手动保存。
6. 完成后仍通过原来的 ZIP 导出按钮交付给 Unity。

## 格式

- 根字段：`format: "mida-localization-translations"`、`formatVersion: 1`、`projectId`、`lineageId`、`language`、`exportedAt`、`tasks`。
- 任务字段：`partName`、`language`、`taskVersion`、`context`、`entries`。
- 词条字段：`key`、`currentSource`、`speakerKey`、`speakerChineseName`、`context`、`translation`。
- `context` 保存章节、小游戏资产及空译文许可等来源信息；必须保留，不能修改。
- 文件为 UTF-8 JSON，支持 UTF-8 BOM，上限 32 MiB、1,000 个任务、100,000 条词条。

## 匹配与计数

项目、版本谱系和目标语言必须匹配当前空间。根据任务身份、词条 key、中文原文、发言人和来源上下文精确匹配，不按数组顺序、行号或相似中文匹配。文件内重复任务、重复 key 或格式错误会拒绝整份文件。

允许较旧任务版本中的候选用于新版中来源完全未变的词条；较新版本、已删除、来源已变化的词条跳过。已确认词条可以新增待校验候选，但不会因 JSON 导入直接被覆盖或变回未确认。导入结果列出可用数量及各类跳过数量。

再次导入时，只替换本次文件中有效词条的候选，包括已有确认译文的词条。候选按最近一次成功导入为准，不根据可手工编辑的文件时间戳判断新旧；没有出现或尚未填写的条目不清除已有候选。候选随本机工作区和备份保存，不进入 Unity ZIP。导入新版 ZIP 后会清除来源已变化或删除词条的候选，来源未变的已确认词条仍可保留候选。

待校验框旁的“确认”复用现有工作量去重规则：第一次完成当前中文的有效新译文按 `han-v1` 记录；相同中文重复采用、已有确认译文润色、未改译文的复核不重复计数。当前中文发生变化后的有效重译可产生新的工作记录，原记录继续保留。实际对账仍以交付 ZIP 根目录 `manifest.json` 的 `workload` 字段为准。

## 给 AI 的内容

将整个导出文件交给 AI，要求保留结构和其他字段，只填写或修改 `translation`，并返回纯 JSON。`currentSource` 是只读中文，`translation: null` 是待填写的目标语言译文；开启“导出已翻译的内容”后，已有译文字符串也可以用于校对。不是仅凭中文配对：必须保留 `key`、项目、语言和来源字段，避免同一句中文出现在不同任务时错配。
